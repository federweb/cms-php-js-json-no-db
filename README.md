# SpartanCMS

A database-free CMS in PHP 8 (8.0+), JS, CSS and JSON. Built for two things only:
**search engine visibility** and **speed** — without ever getting in the way of the
developer. Every page is your own HTML+PHP, your own CSS, your own JS.

- ~1.5 ms to render a page, ~4 MB peak memory, no database, no dependencies
- Runs on PHP 8.0+ (shared hosting friendly) and in any subfolder, unconfigured
- Complete technical SEO out of the box: canonical, hreflang, Open Graph,
  Twitter cards, Schema.org `@graph`, sitemap.xml, robots.txt
- HTML5-valid, accessible output (skip link, landmarks, `aria-current`)
- Backend with the Ace editor for HTML/PHP, CSS, JS and JSON-LD

---

## 1. Install

```bash
# 1. copy the files into the web root
# 2. set the backend password in config.php
php -r "echo password_hash('your-password', PASSWORD_DEFAULT), PHP_EOL;"
#    paste the result into CMS_ADMIN_PASSWORD

# 3. seed the JSON tables and the bilingual demo site
php install.php          # or open install.php in the browser

# 4. remove the installer
rm install.php
```

Then open `backend.php` (default password: `admin`) and set **Site URL** under
*Settings* — canonical URLs, hreflang and the sitemap are built from it.

Requirements: PHP 8.0+ and URL rewriting. Write permission is needed on
`data/`, `media/` and on the CMS folder itself (for `sitemap.xml` / `robots.txt`).

### Subfolder installs (`https://site.com/CMS/`)

Nothing to configure: `CMS_BASE_PATH` is detected from the running script and
`.htaccess` deliberately ships **without** `RewriteBase`, so Apache resolves the
rewrites against the real directory.

> Do not set `RewriteBase /` when the CMS lives in `/CMS`: every inner page
> would be rewritten to `/index.php` at the domain root and return 404 while the
> homepage keeps working (it is served by `DirectoryIndex`, no rewrite involved).
> That is the single most common cause of "the homepage works, the other pages
> don't". Only set `RewriteBase /CMS` if your host uses an `Alias` and the
> automatic resolution fails.

Two things still need a human decision in a subfolder install:

1. **Settings → Site URL** must include the subfolder
   (`https://site.com/CMS`), otherwise canonical, hreflang, Open Graph and the
   sitemap advertise the wrong host. Left empty, the CMS derives it from the
   request (honouring `X-Forwarded-Proto` / `X-Forwarded-Host` behind proxies
   such as Cloudflare or the Aruba front end), which is fine for development but
   not for production.
2. **robots.txt** is only read from the domain root, so copy the generated file
   to `https://site.com/robots.txt`, or add its `Sitemap:` line to the existing
   one. The backend reminds you of both under *Sitemap & SEO*.

### nginx

`.htaccess` is ignored by nginx. Add this to the server block:

```nginx
location /CMS/ {
    try_files $uri $uri/ /CMS/index.php$is_args$args;
}
location ~ ^/CMS/(data|includes)/     { deny all; }
location = /CMS/config.php            { deny all; }
location ~* ^/CMS/media/.*\.(php|phtml|phar)$ { deny all; }
```

At the domain root, drop the `/CMS` prefix from every line. Without such a rule
a front controller in the parent directory will swallow the requests and the
inner pages will never reach the CMS.

## 2. Files

```
index.php          front controller: routing, canonical redirects, output
backend.php        the whole administration (single file)
config.php         hardcoded password, paths, head components, output options
template.xml       site positions (header / page / footer) and their order
install.php        installer + demo content (delete after use)
.htaccess          rewrites, compression, cache, security headers
sitemap.xml        generated by the backend
robots.txt         generated by the backend

includes/core.php    JSON store, referential integrity, template helpers
includes/seo.php     head builder, Schema.org graph, sitemap, robots
includes/render.php  page assembly

data/*.json        the "database" (one file per table, ids + auto increment)
media/             uploads (PHP execution disabled by its own .htaccess)
```

## 3. Data model

Every table is `{ "auto_increment": N, "rows": [ ... ] }`. Writes are atomic
(temp file + `rename`) and guarded by an exclusive lock, so concurrent requests
can never corrupt a file. Backup = copy the `data/` folder.

| Table | Key fields |
|---|---|
| `languages` | `id, code, name, native_name, locale, hreflang, direction, is_default, active, sort` |
| `pages` | `id, name, slug, lang, is_default, status, translation_group, html, css, js, schema, meta_*, og_*, robots_*, sitemap_*, head_extra, body_class` |
| `menu` | `id, menu, lang, label, page_id, url, parent_id, sort, target, rel, active` |
| `blocks` | `id, position, lang, html, css, js` (header, footer, any position in `template.xml`) |
| `settings` | single row: site identity, SEO defaults, Schema.org, `global_css`, `global_js` |
| `media` | `id, file, original_name, mime, size, width, height, alt` |

**Referential integrity** is enforced by the backend, not by the file format:

- a language cannot be deleted while pages, menu items or blocks still use it,
  and at least one active language must remain;
- renaming a language code rewrites `lang` in pages, menu items and blocks;
- deleting a page deactivates the menu items pointing at it and rebuilds the sitemap;
- the homepage of a language cannot be deleted;
- a menu item cannot link to a page of a different language;
- *Sitemap & SEO → Check references* repairs any dangling `page_id` / `parent_id`.

## 4. Page structure

Each page carries the five sections the backend edits in tabs:

1. **HTML + PHP** — the markup, executed as a normal PHP template
2. **CSS** — inlined in `<head>` for this page only
3. **JS** — inlined before `</body>` for this page only
4. **Schema.org** — JSON-LD merged into the system `@graph`
5. **Meta tags + SEO** — title, description, canonical, OG/Twitter, robots, sitemap

### Helpers available inside page and block code

```php
e($string)                          // HTML escaping (always use it on variables)
$page, $lang, $settings             // current page row, language code, settings

cms_page_url($page|$id)             // root-relative SEO URL of a page
cms_page_abs_url($page|$id)         // absolute URL
cms_media('photo.webp')             // /media/photo.webp
cms_setting('site_name')            // any setting
cms_current_page() / cms_current_lang()

cms_menu_html('main', 'it', [       // accessible nested <nav><ul> with aria-current
    'nav_class' => '', 'ul_class' => '', 'li_class' => '', 'a_class' => '',
    'aria_label' => 'Main menu',
]);
cms_language_switcher(['aria_label' => 'Language']);

Pages::home('it'); Pages::bySlug('it', 'chi-siamo'); Pages::published('it');
Pages::translations($page);         // one row per language, keyed by code
Menu::tree('main', 'it');           // raw tree, to build your own markup
Store::all('media');                // any table, for custom listings
```

Example:

```php
<section class="wrap">
  <h1><?= e($page['name']) ?></h1>
  <?php foreach (Pages::published($lang) as $p): ?>
    <a href="<?= e(cms_page_url($p)) ?>"><?= e($p['name']) ?></a>
  <?php endforeach; ?>
  <img src="<?= e(cms_media('team.webp')) ?>" width="800" height="600"
       alt="Our team" loading="lazy" decoding="async">
</section>
```

## 5. URLs

| Page | URL |
|---|---|
| homepage, default language | `/` |
| homepage, other language | `/en/` |
| inner page, default language | `/chi-siamo` |
| inner page, other language | `/en/about-us` |

One URL per page, enforced with 301 redirects: uppercase → lowercase,
`/it/chi-siamo` → `/chi-siamo` (when the default prefix is hidden),
`/chi-siamo/` → `/chi-siamo`, `/en` → `/en/`, `/index.php` → `/`.

Turn off *Serve the default language without the /xx/ prefix* in Settings to get
`/it/...` and `/en/...` symmetrically.

## 6. What the system emits on every page

```html
<!doctype html>
<html lang="it">
<head>
  <meta charset="utf-8">                       <!-- always first -->
  <meta name="viewport" ...>
  <title>…</title>
  <meta name="description" ...>
  <meta name="robots" content="index, follow, max-snippet:-1, max-image-preview:large, …">
  <link rel="canonical" href="https://…">      <!-- absolute, self-referencing -->
  <link rel="alternate" hreflang="it|en|x-default" …>
  <meta property="og:…">  <meta name="twitter:…">
  <link rel="preconnect" …>                    <!-- only for enabled frameworks -->
  <style>…</style>                             <!-- global + block + page CSS, inlined -->
  <script type="application/ld+json">{"@context":"https://schema.org","@graph":[…]}</script>
</head>
<body class="lang-it">
  <a class="skip-link" href="#main">…</a>
  <header id="site-header">…</header>
  <main id="main">…</main>
  <footer id="site-footer">…</footer>
  <script>…</script>                           <!-- global + block + page JS, inlined -->
</body>
```

The `@graph` always contains `Organization` (or LocalBusiness/Person),
`WebSite`, `WebPage` (typed per page) and, on inner pages, `BreadcrumbList` —
all cross-referenced by `@id`. Whatever you write in the page's Schema.org tab
is merged in: a single node, a list of nodes or `{"@graph":[…]}`. `@context` is
added by the system, and `<` `>` `&` are hex-escaped so a string value can never
close the `<script>` early.

On a 404 response the system deliberately emits **no** canonical, hreflang, Open
Graph or structured data — only `noindex, follow` — because the document does
not represent the requested URL.

CSS and JS are inlined rather than linked: for the small, hand-written amounts a
spartan site needs, that removes two render-blocking round trips. Frameworks
(Bootstrap, UIkit, …) stay external and cacheable — see below.

## 7. Head components (frameworks)

`config.php → CMS_HEAD_COMPONENTS` embeds front-end frameworks system-wide.
Bootstrap 5, UIkit 3, Tailwind (CDN) and Alpine.js ship pre-configured and
disabled; flip `'enabled' => true` on what you need:

```php
'uikit' => [
    'enabled'    => true,
    'preconnect' => 'https://cdn.jsdelivr.net',
    'css' => [['href' => '…/uikit.min.css']],
    'js'  => [['src' => '…/uikit.min.js', 'position' => 'body', 'defer' => true]],
],
```

Enabled components automatically get `preconnect` + `dns-prefetch`,
`integrity`/`crossorigin` when declared, and their scripts land in `<head>` or
before `</body>` according to `position`.

## 8. Template positions

`template.xml` declares the editable areas and the order in which they are
printed. Add a position and it appears in the backend menu immediately:

```xml
<positions>
    <position key="topbar" label="Top bar" scope="lang"/>
</positions>
<layout>
    <slot key="topbar" tag="div" attrs="id=&quot;topbar&quot;"/>
    <slot key="header" tag="header" attrs="id=&quot;site-header&quot;"/>
    <slot key="page"   tag="main"   attrs="id=&quot;main&quot;"/>
    <slot key="footer" tag="footer" attrs="id=&quot;site-footer&quot;"/>
</layout>
```

`scope="page"` marks the slot filled by the page itself (keep exactly one).
`tag=""` prints the block without a wrapper. Blocks are per language, with an
"all languages" (`*`) fallback.

## 9. Backend

`backend.php` — password from `config.php`, session cookie `HttpOnly`+`SameSite`,
CSRF token on every write, brute-force throttling, `X-Robots-Tag: noindex`.

| Section | What it does |
|---|---|
| Dashboard | content counters, SEO health, pages missing description/`<h1>`/with long titles |
| Settings | identity, URLs, indexing, social, Schema.org, injected head/body code |
| Languages | CRUD, default language, activation, integrity checks |
| Menu | multiple menus per language, nesting, ordering, page or custom links |
| Pages | CRUD + duplicate, tabbed editors, draft preview, hreflang cluster view |
| Header / Footer | per-position, per-language HTML+PHP / CSS / JS |
| Global CSS / JS | applied to every page |
| Media | multi-upload, extension whitelist, alt text, dimensions, click-to-copy |
| Sitemap & SEO | generate sitemap.xml + robots.txt, integrity repair, duplicate titles |

The Ace editor (`Ctrl/Cmd+S` saves) handles PHP/HTML, CSS, JavaScript and JSON
with syntax highlighting, soft wrap and a theme that follows the OS.

Drafts are invisible to the public; append `?preview=1` while logged in to see
them (served with `X-Robots-Tag: noindex`).

## 10. Sitemap and robots

Generated from *Sitemap & SEO*, and automatically after every page save.
Included: published pages, flagged for the sitemap, with `index` robots, in an
active language. Each `<url>` carries `lastmod`, `changefreq`, `priority` and
`xhtml:link` alternates for the whole translation cluster.

`robots.txt` blocks `backend.php`, `/data/` and `/includes/`, appends your custom
rules and points at the sitemap. Turning off *Allow indexing* switches both the
meta robots and robots.txt to full `Disallow`.

## 11. Security notes

Page and block code is executed as PHP — that is the point of the CMS, and it
means **backend access equals code execution**. Therefore:

- use a strong password hash in `config.php` and serve the site over HTTPS;
- keep `backend.php` behind an extra layer if you can (IP allowlist, basic auth);
- `data/` and `includes/` are denied by `.htaccess`; `media/` has PHP execution
  disabled and serves SVG under a restrictive CSP;
- uploads are extension-whitelisted, size-limited and renamed to safe slugs.

On nginx, replicate the rewrite in your server block:

```nginx
location / { try_files $uri $uri/ /index.php?$query_string; }
location ~ ^/(data|includes)/ { deny all; }
location ~ ^/config\.php { deny all; }
location ~* ^/media/.*\.(php|phtml|phar)$ { deny all; }
```

## 12. SEO checklist verified on the generated output

`<title>` unique per page · meta description · one `<h1>` · `<html lang>` ·
viewport · charset in the first 1024 bytes · absolute self-referencing canonical ·
reciprocal hreflang with `x-default` · `og:url` matching the canonical ·
valid JSON-LD with `WebSite` + `Organization` + `WebPage` (+ `BreadcrumbList`) ·
no heading level skipped · every `<img>` with `alt` · every link with
discernible text · sitemap without duplicates, absolute URLs, no `noindex` page ·
HTML5-valid (html5lib strict) on 200 and 404 responses.
